# Mixed per-node leak experiment

Run from the repository root using the existing environment:

```sh
work/study/.venv/bin/python -B -m work.study.mixed_leaks.run_mixed_leaks
```

Open [`results/mixed-leaks-seed24-test104/report.html`](../results/mixed-leaks-seed24-test104/report.html).
Use `--output work/study/results/another-new-directory` for a repeat. The runner
refuses nonempty directories and any path inside or containing `results/latest/`
or `results/selected/`, including resolved symlinks. Results remain Git-ignored.

The local saved selection was verified as `seed24/forward_leak0`, byte-for-value
equivalent to the configuration generated by the original selector. This
experiment reuses that generated topology, so it does not require ignored saved
results to exist in another checkout. Every candidate uses one 16-node, six-bit
`IntegerReservoir`. Only its existing `leak_shifts` change. The model, features,
signed rounding, clipping, simultaneous updates, resets and receiver serialization
are untouched. No second reservoir, conventional ESN, RTL or gate change is added.

The complete settings block is `EXPERIMENT` in [`mixed_leaks.py`](mixed_leaks.py):

| Candidate | Node-order leak shifts | Purpose |
| --- | --- | --- |
| `uniform0`–`uniform3` | One shift repeated 16 times | Uniform controls; 0 reproduces the selected reservoir |
| `alternating02`, `alternating20` | Alternating 0 and 2, in both phases | Fast and slow nodes distributed across the fixed topology |
| `cycle0123`, `cycle3210` | Repeating ascending/descending 0–3 | Four retention scales, with their placement reversed |

Connection indices, recurrent weights and feature weights are identical in every
candidate. These eight settings were specified before fresh held-out evaluation;
they are a small controlled comparison, not an optimized search over placements.
Each complete candidate configuration and all three fitted readouts are saved.

## Memory and recognition

The reset probe starts with 20 low ticks, then two pulses with a three-tick gap.
It compares `(3,8)` with `(8,8)` and `(8,3)` with `(3,3)`. All four samples beginning
at the final falling edge are compared **after** their reservoir update. These are
relative offsets: the compared pulse pairs need not finish at the same absolute
tick. Full-state L1 distances and Hamming distances of sign bits are separate.

Continuous probes prepend every ordered pair of the five nominal pulse patterns,
using 12 and 20 low ticks after each preceding pattern: 50 histories plus reset.
State and feature extraction continue through each prefix and target. All five
patterns also appear as targets, for 255 probe streams. The report records:

- Same-history differences, isolating the first pulse.
- Minimum cross-target distance across independently varying histories, catching
  collisions hidden by a same-history comparison.
- Maximum same-target distance across histories, showing unrelated-prefix effects.
- Actual fitted decisions for each target and each decision offset. The worst
  continuous accuracy across pair/offset groups catches history-dependent errors.

The clean probes are development diagnostics, never fitting data or held-out
evidence. They cover nominal widths and two preceding patterns, not every possible
history. Distance alone cannot establish linear separability or recognition.

Fitting reuses the original three readouts, ridge grid, thresholds, stabilization
choices and validation event-F1 ranking. Training uses 12 streams and validation
6, with 24 patterns each and the original seed-23 distributions. The run-length
reference is selected once on validation and reused for every candidate.

The original screens remain: at least two binary fingerprints, at most 50%
saturation, and a maximum initialization-probe tail gap of one count. Additional
eligibility rules, declared before fitting, require:

1. No full-state collision at any of the four offsets in reset, matched-history,
   or cross-history comparisons.
2. The trained full-state readout is correct at every reset-probe decision tick
   and at least 90% correct for **each** continuous target/offset group.
3. Its validation known-event precision, known-event recall and unknown-tick
   recall each reach 80%.

These experimental requirements are intentionally stronger than state separation.
Sign-bit separation is reported but not mandatory: a full-state diagnostic can
succeed even if sign quantization loses information. Eligible candidates retain
the original joint Hamming/full-state validation ranking. The original study's
selector is not modified. This experiment does not search for alternate threshold
settings satisfying the new constraints; it screens the existing F1-selected
settings. Thus rejection is not proof that no readout settings could ever work.

Every candidate is fitted and evaluated for diagnosis, including candidates that
fail dynamics checks. A failed candidate cannot win. If none pass, selection is
`null`; there is no fallback or relaxed threshold.

## Held-out data and artifacts

`plan.json` records settings, selection policy and source hashes before fitting.
`selection.json` records all diagnostics and rejection reasons. `config.json`
freezes every candidate and the reference **before** test generation. The runner
reloads those JSON bytes and then generates fresh seed-104 test streams: six
streams for each original condition, totaling 576 patterns and 384 known events.
All candidates use identical stream objects, seeds and dataset hash. Earlier
inspected test seeds 23 and 24 are development evidence, not a controlled baseline.

`report.html` embeds memory and context plots and links each candidate's original
comparison-style report. `metrics.json` includes clean and aggregate detections,
false detections, unknown recall, latency, provenance and reload status. Individual
reports also show each condition and confusion matrices. `memory_traces.json.gz`
saves all probe inputs, states, scores and decisions; candidate directories save
all test traces. Streaming replay must reproduce states, decisions and events for
every saved test and probe stream. The frozen settings hash must remain unchanged.

Repeated test104 runs are reproducibility checks, not additional independent
evidence. Once these results guide a new experiment, reserve new test seeds and
freeze that experiment's settings before generating its tests.

## Observed run: 2026-10-04

**No candidate passed all requirements. Mixed leaks recovered some memory, but
did not produce a reliable recognizer.** Settings were frozen before the seed-104
streams were generated; no recognition settings changed after inspecting them.

`uniform0` reproduced both documented full-state collisions at all four ticks.
`uniform2`, `uniform3`, `cycle0123` and `cycle3210` retained full-state differences
for both comparisons through all four ticks, including all 50 continuous histories.
No candidate preserved sign-bit distinctions for both comparisons at every tick.
All seven nonzero-leak configurations failed the unchanged initialization screen,
with maximum residual gaps of 3–39 counts versus the permitted one. None exceeded
the 50% saturation ceiling.

The two cycle mixtures illustrate the remaining problem:

- `cycle0123` had continuous minimum L1 distances `[7,6,5,4]` for `(3,8)` versus
  `(8,8)`, and `[18,17,16,15]` for `(8,3)` versus `(3,3)`. Same-target prefix
  variation was smaller: one count and three counts, respectively.
- `cycle3210` retained only `[1,1,1,1]` for the long-ending comparison, equal to
  its maximum prefix diameter. Its short-ending distances were `[20,16,14,13]`.
- Both full-state readouts classified the known probes correctly at every offset
  across every prefix, but classified unknown `(8,8)` as known class 0 at **every**
  decision tick, even after reset. Thus the failure is not merely unrelated prior
  patterns dominating the clean probes. Retained magnitude differences were not
  sufficient for the fitted rejection behavior. Some other unknown decisions
  also depended on prefix history.

`cycle3210` had the strongest **full-state** validation F1, not the strongest
original joint readout score. On held-out streams its Hamming readout emitted no
known detections (0% F1, 100% unknown recall); its sign-bit linear readout had
28.6% F1 and 0% unknown recall. Its full-state readout's matched-event median/p95
latency was 2/3 ticks. On clean streams alone that full-state readout found all
96 known events but emitted 21 false events and recognized only 50% of unknown
ticks. The reference was perfect on those clean streams. The higher aggregate
full-state F1 therefore does not establish successful recognition or rejection.

One narrow next experiment: try a single 16-node feed-forward delay-chain control
with zero leaks, arranged to carry the existing first-pulse age feature through
the fourth decision tick. Keep the arithmetic, features, readouts and screening
requirements fixed. This would test explicit finite memory without relying on
the nonzero-leak integer residuals; its success is not assumed. It is a topology
experiment for later work, not an additional candidate fitted in this run.
