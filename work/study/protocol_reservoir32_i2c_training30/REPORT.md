# 32 sparse nodes, I2C only, 30 epochs

The 32-node main seeds do not all pass the strict I2C gate. All main seeds deliver every valid payload byte-exactly.

All four candidates completed 30 epochs: main seeds 11/29/47 plus the seed-11 original-loss control. There are 120 saved weight checkpoints and 120 optimizer checkpoints. Both previous experiments remain unchanged.

## Controlled comparison

The node count falls from 64 to 32. Four incoming recurrent taps per node give 128 connections (12.5% density), with a fixed graph generated by the same topology-seed rule. The six input features, leak factors, update/quantization equations, eight classes and decision margin remain unchanged. Input, recurrent and readout weights are trained. No new inference memory or protocol decoder was added.

Tick timing is unchanged: one model update per abstract tick, clock low/high 8–12 ticks, 18-tick target stretch requests, six-tick response setup deadline. The live controller, transmitter, peer and independent decoder are reused. No physical Hz value or hardware speed has been established.

The exact same I2C train/dev files were used: 467,802 unique nonpadding training ticks (459,385 transaction ticks), 12 streams, 512-tick TBPTT, Adam .003 and 2,820 updates per candidate. That is 14,034,060 nonpadding tick presentations per candidate and 56,136,240 total. State is continuous across chunks/transactions; padding contributes no loss. The prior weighted loss, original-loss control, protocol-based checkpoint selection and convergence rules are unchanged.

Final data use a new seed family, generated after freezing all selections. The frozen 64-node weights were evaluated on these same cases without retraining. UART was excluded from this experiment.
