## Follow-up priorities

Use the relevant guide to define an explicit profile before modifying a model. Make a requirements-to-tests mapping; keep byte/transaction success, false responses, reset/recovery, latency, and electrical behavior separate. The most consequential missing behaviors are complete UART recovery/error coverage, I2C timing/electrical qualification and arbitration if claimed, and the entire USB packet/transaction/device layer. None is implemented by this documentation change.
